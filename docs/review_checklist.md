# Проверка эталонов вдвоём

- Q01–Q02: подтверждение одним фрагментом.
- Q03: выдача, GET и отзыв. Без C05 неизвестно время отзыва.
- Q04: два полных дайджеста. Без C06 нельзя сравнить копии.
- Q05: персональное право lev и PUT, а не чужой токен.
- Q06: SIGN и PUT различаются. Без C08 неизвестно время подписи.
- Q07: общее правило, граница исключения, пакет, интервал, место.
- Q08: R3 исключает внешнего анонимного получателя.
- Q09–Q10: обе стороны конфликта; роли не создают приоритета.
- Q11: токен не идентифицирует человека.
- Q12: чтение не доказывает умысел.

Для перестановки сравнить полный состав документов: меняется только порядок.
Для удаления проверить отсутствие смысловых дублей изъятого факта.
Для добавления проверить несовместимость и сопоставимую надёжность источников.
В Q11/Q12 исходно insufficient: один новый документ содержит две противоположные позиции, чтобы появился both. Это обозначенный частный случай теста.

Только после реальной проверки создать review.json:

```json
{
  "dataset_hash": "из manifest.json: config.dataset_hash",
  "reviewed_by": ["Лаптев Егор Игоревич", "Поляков Александр Владимирович"],
  "approved_variants": ["Q01:permutation", "Q01:contradiction"]
}
```

approved_variants включает только проверенные варианты. `python prepare_review.py` создаёт список кандидатов docs/review_candidates.json, не одобрение.
После проверки пересчёт без повторного LLM-прогона:

```bash
python analyze_results.py --results results/run_01 --review review.json
```

Фамилии не заполняются автоматически. Изменение корпуса инвалидирует проверку по отпечатку. Семантические ошибки свободного explanation проверяются отдельно: валидатор JSON не способен доказать его истинность.
