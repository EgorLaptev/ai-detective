## Быстрый запуск

Python 3.11/3.12:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python validate_data.py
python -m pytest -q
streamlit run app.py
```

Приложение открывается на http://localhost:8501. Можно читать досье и менять контекст без модели. Для живого ответа нужен OpenAI-совместимый сервер, например локальный LM Studio. API-ключи не входят в файлы проекта.

```bash
# Linux/macOS
export LLM_BASE_URL=http://localhost:1234/v1
export LLM_API_KEY=local-key
# PowerShell: $env:LLM_BASE_URL="http://localhost:1234/v1"
python run_experiment.py --backend api --model Qwen/Qwen2.5-7B-Instruct --output results/run_01
```

Имя модели должно совпадать с именем на сервере. Для всех режимов используется один backend/модель и одинаковые параметры. Не объединять запуски разных моделей или квантизаций.

## Google Colab

`Lab6_Colab.ipynb` содержит весь проект внутри: скачивать исходные файлы с GitHub или вручную загружать ZIP не требуется. Откройте ноутбук в Colab, выберите CUDA GPU и выполните все ячейки. Зависимости и модель скачиваются из PyPI/Hugging Face. Доступ к Gmail, Google Drive и личным репозиториям не нужен.

Выбрана Qwen/Qwen2.5-7B-Instruct в 4-bit NF4. Длинный контекст не усекается; при превышении 32768 токенов запрос завершается явной ошибкой. KV cache выгружается в RAM. Возможность полного прогона на конкретном GPU и время работы ещё не проверены. При нехватке памяти менять одинаковые для всех режимов технические настройки и начинать новый прогон, не сокращать A незаметно.

Результаты сохраняются после каждого ответа. Повторный запуск с той же папкой пропускает уже записанные запросы. Время жизни `/content` зависит от Colab; до отключения runtime нужно скачать итоговый ZIP. Старый каталог с ошибками не превращается автоматически в новый успешный прогон: для повторения ошибочных запросов использовать новую output-папку.

План: 36 базовых запросов + 36 перестановок + 12 удалений для Q03–Q06 + 36 добавлений противоречия = **120 запросов**. Удаление не применяется к остальным типам, что явно отражено в интерфейсе. Перестановка влияет на A; в B/C порядок независимого индекса остаётся фиксированным, и это контроль неизменности.

## Честность сравнения

- Один системный промпт, temperature=0, max_new_tokens=384, seed=42; Transformers использует greedy decoding.
- BM25 ранжирует текст claims вместе с цитатами. Нет добавления gold-фактов в top-15.
- B/C имеют одинаковый набор ID, одинаковые поля и текст. C меняет только порядок и заголовки ветвей.
- A получает полные документы с C-маркерами перед дословными цитатами. Ему не передаются пересказы gold или рабочая истина.
- Источник, статус claim и время события — отдельные уровни. Normative direct не равно установленному событию: отдельная группа источника имеет a0=2. Согласованные исключения имеют a1=2.
- p=3, код a0+3*a1+9*a2. Расстояние считается по общему префиксу, не разности кодов.
- Пустое/неизвестное время и нормативный интервал относятся к a2=2. Окно события: 18:42–18:50 включительно.
- Невалидные JSON не чинятся и не превращаются в успех. Каждый запрос сохранён вместе с raw, ошибкой, промптом, доступными ID и конфигурацией.

## Проверка людьми и результаты

Читайте docs/review_checklist.md, docs/TRUTH.md и docs/review_candidates.json. Итоговые stress-метрики исключают неподтверждённые варианты. `provisional_includes_unreviewed.csv` — диагностическая таблица, не отчётный результат.

После реального прогона:

```bash
python analyze_results.py --results results/run_01
# После совместной проверки:
python analyze_results.py --results results/run_01 --review review.json
```

Создаются row_metrics.csv, summary.csv, stability.csv и **черновик** report_draft.md/pdf по фактическим ответам. Это не готовый к сдаче отчёт: нужно разобрать реальные объяснения и дополнить качественный анализ. До запуска отчёт не формируется.

Метрики: accuracy статуса по всем запросам; macro evidence P/R/F1; counterevidence recall по вопросам с непустым эталоном; recall распознавания both/insufficient; доля ошибочных ответов confidence>=0.8 на исходном insufficient; число токенов и время; Brier правильности статуса по валидным ответам с отдельной долей валидности. Evidence для contradicted — основания опровержения. Пустые gold и prediction дают evidence F1=1, но в текущем gold основания непустые.

Стабильность: смена статуса и Jaccard evidence по валидным парам, ожидаемая реакция по всем проверенным изменённым запросам. Пропавшие/невалидные ответы не считаются стабильными. При API число токенов может отсутствовать, оно не заменяется оценкой.

Pydantic проверяет структуру, границы confidence и доступность ссылок. Он не способен гарантировать истинность свободного explanation. Запрет выдуманной догадки при insufficient реализован требованием answer=null; семантика explanation проверяется участниками.

## Структура

- data/: 10 документов, claims, questions и авторский сборщик корпуса.
- src/: поиск, дерево, контекст, схемы, LLM, эксперименты и метрики.
- prompts/system.txt: единственный системный промпт.
- tests/: модульные проверки и Streamlit AppTest.
- docs/: рабочая истина, проверка gold, вклад, демонстрация, аудит retrieval.
- AI_LOG.md: 12 эпизодов работы с ассистентом.
- results/: фактические результаты после запуска; в исходном комплекте их нет.
- Lab6_checks.ipynb: выполненные проверки данных и кода без LLM.
